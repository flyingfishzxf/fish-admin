# Scaffolding your own app

FishAdmin ships as a working demo, not as a blank page. `pnpm scaffold` turns a clone into the skeleton of your own product: it rebrands every identity, and optionally removes the parts you are not going to use — the component catalog, the extra locales, and the mock API with the Playwright suite that drives it.

Two starting points, both supported:

- **Read the demo first.** `pnpm install && pnpm dev`, browse the screens, then delete what you do not need. Nothing is rewritten.
- **Scaffold first.** Run the steps below in a fresh clone and start from an app that already carries your name.

## Run it

The script needs the template's own dependencies (Prettier to reformat what it rewrites, Vite to regenerate the route tree), so install before you scaffold:

```bash
git clone <repository-url> my-app && cd my-app
pnpm install
pnpm scaffold
```

The interactive run asks for a package name, a display name, a tagline, and then yes/no for the mock API, the component catalog and every locale except `en` (the fallback language is always kept). Answer with the defaults to get a pure rebrand.

Non-interactive, with `--flag=value` (the equals sign is required):

| Flag                    | Default   | Effect                                                                           |
| ----------------------- | --------- | -------------------------------------------------------------------------------- |
| `--name=<slug>`         | directory | npm-style package name. Also becomes the `localStorage` key prefix.              |
| `--display-name=<text>` | derived   | Brand in the shell, the boot screen, the document title and the Open Graph tags. |
| `--tagline=<text>`      | kept      | Subtitle under the brand. Left out, the template's own tagline survives.         |
| `--mock=keep\|drop`     | `keep`    | `drop` removes the demo backend and everything that depends on it.               |
| `--catalog=keep\|strip` | `keep`    | `strip` removes `/ui`, `/components` and the component catalog.                  |
| `--locales=en,zh-CN`    | all       | Which locales to keep. `en` cannot be dropped.                                   |
| `--target=<dir>`        | cwd       | Directory to transform.                                                          |
| `--dry-run`             | —         | Print the plan without writing a single file.                                    |
| `--yes`                 | —         | Accept every default, no prompts.                                                |
| `--force`               | —         | Run again in a directory that already has a `.scaffold.json`.                    |

`--dry-run` is the cheap way to read the plan before applying it.

## What changes

**Rebrand** — `package.json` name and description, `<title>` and the six Open Graph / Twitter meta tags in `index.html`, the boot screen, `APP_NAME` / `APP_TAGLINE` in `src/lib/document-title.ts`, `app.name` / `app.tagline` in every kept locale bundle, the Vite plugin name, the Docker Compose service and image, and the `fish-admin:` storage prefix.

That prefix is the part that cannot be done by hand in one sitting: ten files read and write the same keys — `public/theme-bootstrap.js` runs before any module, plus the i18n, auth and theme stores, the saved-views and user-table preferences, the mock database and two specs. Rename one of them and a stored theme silently stops being read.

**`--catalog=strip`** — deletes `src/features/playground`, the `/ui` and `/components` routes, `src/config/components.ts` and its test, the two catalog specs, the catalog baseline screenshot, and `catalog.json` / `ui.json` in every locale. It also drops the two `AppPath` members and their nav entries in `src/config/nav.ts`, removes the catalog tests from `e2e/a11y.spec.ts` and `e2e/visual/pages.spec.ts`, and swaps `/components` for `/projects` in the `e2e/security.spec.ts` crawl. Finally it runs `vite build` once, because `src/routeTree.gen.ts` is generated by the router plugin and `pnpm typecheck` runs before the first build.

**`--locales=<list>`** — deletes the dropped locale directory, its three imports, its `SUPPORTED_LANGUAGES` entry and its resource block in `src/lib/i18n.ts`, rewrites `e2e/i18n-theme.spec.ts` down to the theme assertions and drops the Chinese login audit from `e2e/a11y.spec.ts`. The language switcher and the command-palette entry hide themselves when only one locale is left.

**`--mock=drop`** — deletes `src/mocks`, `public/mockServiceWorker.js`, `src/features/settings/api.ts` and `src/config/demo.ts`; removes the MSW bootstrap from `src/main.tsx`, the mock keys from `src/config/env.ts` and `.env.example`, the demo-account cards from the login page, the MFA hint from the OTP page, the "Reset demo data" card from settings, `VITE_ENABLE_MOCK` from the Dockerfile and Compose, and the `msw` / `@faker-js/faker` dev dependencies.

Because the Playwright suite drives the app through the demo backend, dropping the mock drops the whole browser subsystem: `e2e`, both Playwright configs, the visual scripts, the `test:e2e` / `test:visual*` / `perf` scripts, and the `e2e` and `visual` jobs at the end of `.github/workflows/ci.yml`. What is left — Vitest, ESLint, typecheck, the build and the bundle budget — still runs.

## After scaffolding

```bash
pnpm format && pnpm lint && pnpm typecheck && pnpm test && pnpm build
```

Then, by hand:

- `src/config/nav.ts` — the nav is the map of the app. Rename the groups you kept and delete the demo screens you are not building yet.
- `pnpm test:visual:update` inside Docker (`pnpm test:visual:docker`) — the committed baselines still show the FishAdmin brand.
- `docs/` — the template documentation is bilingual and describes the demo. Prune it, or keep it while you are still learning the codebase.
- `.scaffold.json` — the marker recording what was applied. Delete it to scaffold again, or pass `--force`.

## What it does not do

- It does not run `pnpm install`, and it does not fetch anything.
- It does not empty the demo dataset. The mock rows stay, so the screens have content to show; clearing them is a data decision, not a naming one.
- It does not publish anything. `package.json` keeps `"private": true`, so `pnpm create fish-admin` is not available — clone, then scaffold.
- It does not remove the security caveat. The login, the RBAC guards and the mock API stay a client-side UX layer, and the footer keeps saying so. Read [rbac.md](rbac.md) before you reuse any of it behind a real backend.

## Why the plan cannot rot

`scripts/scaffold.test.mjs` runs with `pnpm test` and validates every anchor in the plan against the template in three shapes — rename-only, catalog and locale strip, and full strip including the mock API. Reformat or rename a targeted file without updating the script and the suite fails with the exact anchor and the number of times it matched. The same check is what makes `--dry-run` useful. Inside a scaffolded product the file self-skips: its anchors describe the template, not the copy.
