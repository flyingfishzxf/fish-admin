# FishAdmin 1.6.0 — 接入可信度工程计划

> 内部规划文档。本计划自身不面向终端用户；各里程碑产出的用户可见文档必须按仓库惯例同时提供
> `docs/en/` 与 `docs/zh-CN/` 两份，并保留 client-side RBAC 非安全边界的免责说明。

- 基线：`v1.5.0`（`origin/main` = `9c1d138`，annotated tag object `946ac3e`）
- 计划日期：2026-10-25
- 定位不变：**企业级中后台模板**。本计划不引入真实后端，理由见「范围外」。

## 目标

两件事一次性解决：

1. 别人把 FishAdmin 接到自己 API 上时，**第一周不痛苦**（M1、M2、M5）。
2. 打开仓库和镜像时，**一眼看得出能上生产**（M3、M4）。

## 参照系结论（为什么不需要后端）

模板的价值恰恰是不绑后端。vue-vben-admin v5 的 `apps/backend-mock` 是一个 `"private": true` 的
Nitro 服务，只为 demo 提供 auth/menu/system 接口，对接真实后端时改 `src/api/request.ts` 的 baseURL；
Ant Design Pro、nest-admin 同构。市面上不存在"带生产后端的中后台模板"。

FishAdmin 已有等价资产：

- `docs/en/api-integration.md` + `docs/zh-CN/api-integration.md` 各 453 行（合计 906 行），
  逐接口契约、error contract、refresh behaviour、「Replacing the mock, step by step」、
  「Testing against a real API」。
- mock 可完整摘除：非 mock 构建的 `dist/assets` 中匹配 `mock|browser|msw` 的 chunk 数为 **0**，
  `src/main.tsx:22` 的动态 import 被完整 tree-shake；`POST /api/__mock/reset` 在生产构建里不可达。

因此模板的商业及格线是**缝合点质量**，不是后端。

## M1 — 单一请求客户端 + 超时/中止（约 1.5 天）

**问题**

- `src/lib/api-client.ts:29` 是唯一通用层，但无超时；`signal` 形参（`api-client.ts:11`）没有任何调用方传入，是死代码。
- `src/features/auth/api.ts:40-65` 私自实现了第二份 fetch，无 401 刷新、无重试、无 signal；
  同文件 `:138` 之后的接口又走 `apiRequest`。两条路径在对接真实后端时必然分叉。
- `src/lib/api-error.ts:4` 的 `details` 字段从未被填充（`api-client.ts:16-27` 只解析 `{code,message}`），字段级校验丢失。
- `src/config/env.ts` 用 fallback 静默兜住非法配置，无启动校验。

**任务**

1. `RequestOptions` 增加 `token?: string`（显式 bearer，用于登录前请求与 `/auth/me`）。
2. 把 `src/features/auth/api.ts` 中 10 个走私有 `request()` 的函数改指 `apiRequest`，删除
   `api.ts:40-65` 整段。
3. **防刷新递归**（本里程碑唯一真实回归风险）：`/auth/login`、`/auth/mfa/verify`、`/auth/refresh`
   必须以 `auth: false, retry: false` 调用，否则 `api-client.ts:44` 的 401 → `refreshSession()` 会自调用。
4. 超时：`AbortSignal.any([callerSignal, AbortSignal.timeout(env.requestTimeout)])`；
   新增 `VITE_REQUEST_TIMEOUT`（默认 `15000`），同步 `src/config/env.ts`、`src/vite-env.d.ts:6`、`.env.example`、
   `docs/en|zh-CN/api-integration.md`。超时须映射为 `ApiError(0, 'REQUEST_TIMEOUT')`（实施时定了更明确的名字），不得让 `DOMException` 泄漏到 toast。
5. 串接 TanStack 的 signal：11 个 `src/features/*/queries.ts` 的 `queryFn: ({ signal }) => …`
   （audit / dashboard / departments / files / integrations / notifications / permissions / projects / reports / roles / users），
   对应 `features/*/api.ts` 的 fetch 函数增加可选 `signal`。
6. `src/config/env.ts` 做启动校验，非法值抛错而非静默 fallback。原计划用 zod（已是依赖），
   实施时改为手写整数/布尔校验：`env.ts` 被 `api-client.ts` 拉进首屏图，`import { z } from 'zod'`
   会把整个 zod chunk（gzip 23.1 KB）算进 `firstPaintJs`，实测 164.7 KB → 188.1 KB、直接冲破 180 KB
   预算。校验逻辑只有两个分支，不值得用首屏换。
7. 补 `VITE_UPLOAD_TIMEOUT`（默认 `60000`，文档范围 1000–600000），只给两个 base64 上传点
   （`uploadFile`、`uploadProjectAttachment`）使用。15s 全局上限会把慢速链路上的大附件直接砍断，
   而 M1 之前上传根本没有超时——不补这一条就是模板对外接口的真实回归。

**验收**

- `grep -rn "fetch(" src --include=*.ts` 只命中 `src/lib/api-client.ts`。
- 新增单测覆盖：超时中止并归一为 `ApiError`；`/auth/refresh` 不触发递归刷新；列表翻页时旧请求被 abort。
- 全部门禁复跑绿（见「门禁复现」）。

**执行记录（2026-10-25，已完成）**

- 门禁：`format:check` / `lint` / `typecheck` 通过；77 文件 429 单测全绿，覆盖率 77.41% stmts /
  80.62% branch / 69.52% funcs / 78.04% lines；`pnpm size` firstPaintJs 165.0 KB（v1.5.0 基线 164.7 KB）、
  largestAsyncJs 95.6 KB、totalJs 750.1 KB、totalCss 22.1 KB；`pnpm test:e2e` 70 通过；
  `pnpm test:visual:docker` 14 通过。
- 真实浏览器（demo 构建 + MSW，注入挂死请求验证）：登录 401 不再清会话也不触发 refresh；
  `/auth/me` 用显式 bearer；每个请求都带 signal；离开 `/users` 时未完成的列表请求以
  `AbortError` 取消且界面不报错；挂死的 `/api/roles` 在 15,015 ms 被 `TimeoutError` 中止，
  重试两次后显示"You couldn't load this content. Please try again."，没有 `DOMException` 泄漏。

## M2 — mock 默认安全（约 0.5 天）

**问题**

- `Dockerfile:15` `ARG VITE_ENABLE_MOCK=true`：任何人 `docker build` 出来的"生产"镜像都带 73 个 mock handler。
- `Dockerfile` 运行时阶段无 `USER`，nginx 以 root 启动；基础镜像固定 tag 但无 digest。
- `docker-compose.yml` 无 `healthcheck`、无 labels。
- `.env.development` 与 `.env.production` 被提交在仓库里（不含密钥，但违背惯例）。

**任务**

1. `Dockerfile:15` 默认改为 `ARG VITE_ENABLE_MOCK=false`；demo 镜像显式 `--build-arg VITE_ENABLE_MOCK=true`，
   写入 `docs/en|zh-CN/deployment.md`。
2. 运行时阶段改 `nginxinc/nginx-unprivileged`（监听 8080，非 root），`docker-compose.yml` 同步端口映射并补
   `healthcheck`；两个阶段的基础镜像补 digest。
3. 停止跟踪 `.env.development` / `.env.production`，`.gitignore` 中放行 `!.env.example`。
   行为等价性由 `src/config/env.ts` 兜底（dev = mock on，build = mock off），确保贡献者 clone 后行为不变。
   实施时兜底条件用 `import.meta.env.MODE === 'development'` 而不是原计划的 `import.meta.env.DEV`：
   Vitest 下 `DEV === true` 而 `MODE === 'test'`，用 `DEV` 会让单测里的 `env.enableMock` 变成 `true`，
   把 M1 已提交的默认值断言（`enableMock: false`）改掉。`src/main.tsx` 不读 `env.enableMock` 而是就地
   比较 `import.meta.env` 字面量——运行时对象无法被折叠，`browser-*`（gzip 327 KB）会留在每个生产构建里，
   `totalJs` 800 KB 预算当场就破；实测折叠生效（`pnpm build` 无 `browser-*`）。
4. 追加：`vite.config.ts` 在 mock 关闭的构建里删掉从 `public/` 复制出来的 `mockServiceWorker.js`，
   否则「仅 API 镜像」的产物根目录仍躺着一个 MSW worker 脚本，验收口径不好交代。
   开关的解析规则与 `env.ts` 一致（显式值优先、空值视为未设置、未设置时按 mode 兜底）。

**验收**

- 默认 `docker build` 产物中检索不到 mock 代码；容器以 uid ≠ 0 运行且 healthcheck 通过。
- clone 后不写任何 env 文件，`pnpm dev` 仍有 mock、`pnpm build` 仍无 mock。

**执行记录（2026-10-26，已完成）**

- 门禁：`format:check` / `lint` / `typecheck` 通过；77 文件 431 单测全绿（比 M1 多 2 条 mock 兜底用例），
  覆盖率 77.41% stmts / 80.62% branch / 69.52% funcs / 78.04% lines；`pnpm size` firstPaintJs 165.0 KB、
  largestAsyncJs 95.6 KB、totalJs 750.0 KB、totalCss 22.1 KB；`pnpm test:e2e` 70 通过；
  `pnpm test:visual:docker` 14 通过、零 diff。
- 容器：默认 `docker build` 的 `assets` 中匹配 `browser|mock|msw` 的 chunk 为 0，`mockServiceWorker.js`
  不在站点根目录；容器 `id -u` = 101，`netstat` 显示 `0.0.0.0:8080`，`GET /healthz` 返回 `ok`，
  `docker ps` 约 10s 转 `healthy`。`--build-arg VITE_ENABLE_MOCK=true` 重新构建后 `browser-*.js` 与 worker
  脚本回来了；`docker compose up --build` 起来是 `Up (healthy)`、`0.0.0.0:8080->8080/tcp`。
- digest 取自多架构 index（经镜像站 `Docker-Content-Digest` 核对，不是单平台 manifest）：
  `node:24-alpine` = `sha256:06d7adf3…33918b53`，`nginxinc/nginx-unprivileged:1.29-alpine`
  = `sha256:0c79d56a…104c7fbe6`。
- 真实浏览器：`:5211` dev（仓库已无任何 `.env` 文件）→ worker 已注册且 `navigator.serviceWorker.controller`
  指向 `/mockServiceWorker.js`，登录进 `/`、`/users` 渲染 6 行、`/settings` 出现 Demo data 卡；
  `:5212` dev 显式 `VITE_ENABLE_MOCK=false` → 完全没有注册（显式值压过模式兜底）；
  `:4179` 跑 `pnpm build` 产物 → 无注册，登录给出 "Sign-in failed. Check your credentials and try again."
- 与计划的两处偏差已在上文任务 3/4 记录：兜底条件用 `MODE === 'development'` 而非 `DEV`；
  compose 未重复写 `healthcheck`（镜像的 `HEALTHCHECK` 会被 compose 继承，再写一份只是副本）。

## M3 — 安全头与供应链门禁（约 2 天，最大块）

**前置硬约束**：`index.html` 含一段**内联 `<script>` 主题引导**（防 FOUC）与内联 `<style>`。
`script-src 'self'` 会直接打死主题引导，因此必须先外置再上 CSP。

**任务**

1. 主题引导脚本外置为 `public/theme-bootstrap.js`（`<head>` 内同步加载，置于样式之前）；
   内联 `<style>` 移入 `src/styles/boot.css`。
2. CSP 定稿：
   `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:;`
   `font-src 'self' data:; worker-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'self';`
   `form-action 'self'; frame-ancestors 'self'`
   - `style-src 'unsafe-inline'` 有意保留：React / Radix / recharts 大量写内联 style 属性，去掉会崩布局；文档写明理由。
   - `img-src data: blob:` 是现有 base64 头像与文件预览的硬需求（`src/mocks/handlers/files.ts` 上传路径）。
   - 不加 `upgrade-insecure-requests`：`docker compose` 在纯 http 的 localhost 下会自伤；HSTS 只在 Vercel 边缘加。
3. 重写 `nginx.conf`：当前 `location /`（`nginx.conf:37`）**一条安全头都不发**，而
   `nginx.conf:19-35` 两个静态 location 各自重复四行（`add_header` 不向下继承）。
   改为单一带头片段 + `include`，三条 location 全部覆盖；`vercel.json` 同步同一策略，
   使 demo 与自托管表现一致。
4. 新增 `e2e/security.spec.ts`：
   - 断言 `/`、`/index.html`、`/assets/*` 三处响应头齐全且一致；
   - 遍历主要 flow 期间监听 `securitypolicyviolation`，事件数必须为 0。
     **这条测试是 M3 的验收器，不接受仅靠肉眼检查。**
5. 供应链自动化：
   - 新增 `.github/dependabot.yml`（npm + github-actions，weekly，按 major/minor 分组）；
   - 新增 `.github/workflows/codeql.yml`；
   - `ci.yml` 顶部补 `permissions: contents: read`（当前无任何 `permissions:`，使用默认宽权限 token）、
     quality job 增加 `pnpm audit --audit-level=high`、build job 成功后上传 `dist` 产物、补 `workflow_dispatch` 触发。
6. 文档：新增 `docs/en/security-headers.md` 与 `docs/zh-CN/security-headers.md`；README「Quality gates」补一行。

**验收**

- `curl -I` 三条路径头一致且含 CSP；新 e2e 绿；CodeQL 与 dependabot 首跑有产出。

## 范围外（下一轮，不是「不需要」）

- **真实后端**：模板不绑后端；本计划只加固缝合点。
- **可观测性最小集**：request-id、`QueryCache`/`MutationCache` 全局 onError、Web Vitals 运行时上报
  （现状：0 telemetry、0 logger、无 `unhandledrejection` 监听，Web Vitals 只在 `e2e/perf.spec.ts:10` 里测）。
- **10k 行规模**：无虚拟化依赖、~19 个列表仅 2 个走服务端分页、导出是客户端 `pageSize:100` 翻页循环、
  seed 只有 57 用户 / 160 审计事件；没有真实数据量之前无法有意义验证，故排在真实对接之后。
- **多租户 / SSO / 数据级权限**。
- **交互一致性还账**：39 处 `onError` + 136 处 `toast.*` 收敛为单一 helper、`ApiError.details` 打通字段级校验、
  乐观更新回滚（全仓 0 处 `setQueryData`）。
