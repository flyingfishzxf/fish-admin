# Vue 模板

`apps/vue-template` 是 FishAdmin 的私有 Vue 3 管理后台。它复用框架无关的 contracts、i18n 资源与 MSW Mock API，以及 `@fish-admin/vue` 组件移植。它是演示模板，不是发布包。

> 客户端权限是体验层，不是安全边界。路由守卫和按钮检查都可以在浏览器中被绕过；
> 真实部署必须在服务端执行授权校验。

## 范围

- 登录（含可选的双因素校验）、登出、会话恢复与 access token 刷新。
- 注册与邮箱验证、找回密码与重置密码、接受邀请——共六个认证入口，全部接到 Mock API。
- 账户域：个人资料（姓名、简介、头像）、账户安全（密码、会话、双因素）与设置（主题模式、强调色、语言、演示数据重置）。
- 壳层：三种布局（侧边栏 / 顶栏 / 混合）、两档密度、三档内容宽度、可持久化的页签工作台、混合布局的分组子导航、命令面板、离线横幅与四步产品导览。
- 通知：带未读角标的顶栏铃铛、`/notifications` 收件箱（筛选、勾选、单条与批量已读）、可深链的详情抽屉，以及投递偏好卡片。
- 按权限过滤的侧边栏、路由守卫与按钮级权限检查。
- 浅色 / 深色 / 跟随系统主题、五种强调色与 en / zh-CN 两种语言，均持久化。
- 工作台：7/30 天区间、四张 KPI 卡片、收入面积图、访问柱图、获客环图与最近活动流。
- 用户：搜索、角色与状态筛选、服务端分页与排序、页大小、行选择与批量改状态/批量删除（都可撤销）、导出筛选结果为 CSV、密度与列显示控制、保存视图、行操作、新建/编辑弹窗与删除确认；另有 `/users/:id` 详情页，含九项资料概览、标签与头像编辑、审计动态时间线和页内「用户不存在」状态；另有四步 CSV 导入向导（上传、列映射、逐行复核、完成）。
- 报表：区间与粒度筛选、四张 KPI、可切指标并带目标线的趋势图、带占比的渠道环图，以及可导出 CSV 的分页表格。
- 部门：`role="tree"` 与方向键导航、成员计数、就地新建与重命名。
- 角色：搜索、新建/重命名/删除，以及按角色逐个请求保存的权限矩阵。
- 权限：13 个分组的参考列表、分组视图与代码搜索。
- 字典：左右双栏维护类型与条目，含条目重排与启用/停用。
- 审计日志：动作、对象与日期筛选，服务端分页，以及带事件 metadata 与关联事件的详情抽屉。
- 集成：连接卡片、服务商与状态筛选、含请求头的表单抽屉，以及可重放的投递记录抽屉。
- 项目：作品集 KPI、精选区、六个筛选、看板与列表（服务端排序）、分页、两步新建弹窗与归档；每个项目在 `/projects/:id` 打开概览（里程碑分组、附件、动态）、四列任务板、可编辑预算与三步复盘，另有成员与设置抽屉。
- 审批流：带三个视图页签（我发起 / 待我审批 / 全部）的收件箱、防抖搜索、状态 / 类型 / 发起人 / 日期区间筛选、请求表格与可调页大小的分页；每张单在 `/workflows/:id` 打开表单、步骤时间线、评论区，以及仅对「当前待我处理」者显示的动作面板（通过 / 驳回 / 转交）。
- 四个整页状态页（401、500、503、维护中），渲染在壳层之外；另有原有的 403 与 404 页。

不包含：用户表的虚拟滚动（React 对 5,000 行数据集做了虚拟化，Vue 表格渲染全部行——对种子数据够用，到那个量级不行）、用户表的交互式列固定（React 只在初始状态把复选框与姓名列固定，Vue 表格也没有 sticky 列渲染），以及页面级像素 parity。**`NAV_CONTRACT` 的 16 个页面现已全部交付。**

## 壳层

三种布局在 `/settings` 选择，与 React 模板共用 `localStorage` 里的 `fish-admin:ui`（同一 key、同一 `{ state, version }` 信封，因此两个模板可以共享同一个浏览器配置）：

| 布局      | 结构                                             |
| --------- | ------------------------------------------------ |
| `sidebar` | 图标轨 + 分组侧边栏；默认值                      |
| `header`  | 无侧边栏；每个分组是顶栏的一个下拉菜单           |
| `mixed`   | 收起状态的图标轨 + 面包屑头部 + 当前分组的子导航 |

- **密度** —— `default` 或 `compact`。紧凑档写 `html[data-density="compact"]`，收窄 `--spacing` 比例，因此 Portal 出去的浮层也会继承。
- **内容宽度** —— `narrow` / `default` / `full` 只作用在 `<main>` 的 class 上，从不改变壳层本身。
- **页签** —— 打开过的可访问页面会留在顶栏下方；页签持久化，可固定、单关、关右侧或全关；当前角色失去权限的页面，其页签会被移除。关闭当前页签会落到剩下的最后一个。
- **命令面板** —— `Ctrl/Cmd+K` 打开，输入即过滤页面与动作，方向键移动，回车执行。`Ctrl/Cmd+B` 收起图标轨，`header` 布局下不生效（那里没有可收起的轨）。
- **子导航** —— 仅 `mixed` 布局：当前分组其余页面的一排胶囊。
- **离线横幅** —— 壳层监听 `online` / `offline`，离线时显示 `role="status"` 横幅，恢复后短暂确认。
- **产品导览** —— 四步（侧边栏、搜索、铃铛、账户），从工作台启动。遮罩走 Portal，锚点不在屏幕上时跳过该步，Esc 关闭。

## 通知

顶栏铃铛显示服务端的未读数（超过九显示 `9+`），点开预览最近五条；「查看全部」进入收件箱。

`/notifications` 把状态放在 URL 里，因此刷新、书签与浏览器后退都能回到同一视图：

| 参数           | 取值                       | 默认  |
| -------------- | -------------------------- | ----- |
| `page`         | 1 到 `pageCount`           | `1`   |
| `pageSize`     | 5–50                       | `10`  |
| `filter`       | `all`、`unread`、`mention` | `all` |
| `notification` | 通知 id；打开详情抽屉      | 无    |

收件箱支持逐行已读/未读、带全选的行复选框（部分选中时呈 indeterminate）、批量「标记所选已读」、头部的「全部已读」以及分页。切换筛选或翻页会清空选择集。打开未读行会标记已读并写入 `?notification=<id>`；关闭抽屉只清这一个参数。底部的投递偏好卡片用草稿编辑静默时段（`HH:mm`）、摘要节奏与站内/邮件/推送三个渠道：没有改动前按钮保持禁用，「重置」只恢复已存值、不发请求。

该域由七个端点支撑，全部由 `packages/mock` 提供：`GET /notifications`、`GET /notifications/:id`、`PATCH /notifications/:id`、`POST /notifications/read`、`POST /notifications/read-all`、`GET /notifications/preferences` 与 `PUT /notifications/preferences`。每次写操作都会失效整个 `['notifications']` 前缀，未读数始终取服务端的值。

## 图表

模板需要的图形只有三种：面积、分组柱、环。它们没有用 Recharts——那个库只服务 React——而是自写成 SVG。几何计算放在 `components/ui/chart/chart.ts`，都是带单测的纯函数，组件只负责渲染。

| 文件             | 职责                                                        |
| ---------------- | ----------------------------------------------------------- |
| `chart.ts`       | `niceTicks`、Fritsch–Carlson 单调插值、环形扇区、分组柱布局 |
| `ChartShell.vue` | 测量容器、画网格与双轴、输出 hover 索引                     |
| `AreaChart.vue`  | 渐变填充，可选虚线目标线                                    |
| `BarChart.vue`   | 分组柱、圆角、底部图例                                      |
| `DonutChart.vue` | 带 3° 间隙的环，环心显示标签提示                            |

SVG 按实测像素宽绘制，而不是从固定 `viewBox` 缩放，这样窄卡片里的刻度文字不会跟着变形。宽度来自 `ResizeObserver`；jsdom 没有它、且所有元素宽度为 `0`，所以 `useChartSize` 回退到 640px，组件测试因此可以只断言结构而不依赖具体像素。

hover 以整张图为单位而不是单点：`ChartShell` 算出索引（面积图取最近点，柱图取所在 band）并抛出，图表据此画指示线与高亮圆点，浮层则是 SVG 上方的 HTML 层，因而能复用界面本身的边框与阴影变量。

颜色由调用方直接给出（`var(--chart-1)`，或取色器返回的十六进制），不像 React 那样先经 `ChartConfig` 织成 CSS 变量再交给 Recharts。`/reports` 的趋势图是唯一允许用户改色的地方，默认 `#6366f1`。

一处有意的偏离：获客渠道的图例让长名称换行，而不是打省略号。三等分卡片里 React 版给环图留 200px，标签列窄到 “Organic search” 只剩 “Organic …”；本模板改成 160px 并允许换行，名称得以完整显示。

## 与 React 模板的偏差

| 领域     | React                                                                       | Vue 模板                                                                             |
| -------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 外壳     | 侧边栏 / 顶栏 / 混合 + 密度与宽度设置                                       | 同样三种布局、两档密度与三档宽度，配置在 `/settings`                                 |
| 导航     | 契约中的全部 16 个页面                                                      | 全部 16 个；没有隐藏项                                                               |
| 认证     | 登录、注册、找回密码、邀请、OTP、2FA                                        | 同样六条流程；不发邮件，TOTP 密钥固定                                                |
| 工作台   | KPI、三张图表、产品导览                                                     | 同样三张图与导览，用自写 SVG 绘制                                                    |
| 用户     | 列控制、密度、保存视图、CSV、批量、导入、详情、动态、虚拟滚动               | 除虚拟滚动外同样对齐；拖拽排序与调宽在应用层实现，不提供交互式列固定                 |
| 角色     | 两步式新建向导，第二步同时选权限                                            | 单一弹窗；权限在矩阵中授予                                                           |
| 字典     | 拖拽手柄与方向键，无分页                                                    | 相同，条目列表不分页                                                                 |
| 审计日志 | JSON 查看器、按动作配图标、防抖搜索、页大小选择                             | metadata 用定义列表、纯文字徽标、无防抖、每页 20                                     |
| 集成     | Combobox、Segmented 状态筛选、数字页码、Popconfirm                          | Select 筛选、上一页/下一页、删除确认弹窗                                             |
| 个人资料 | 头像裁剪、上传进度、时区与语言偏好                                          | 只有姓名、简介与头像；头像在本地重编码为 256×256                                     |
| 账户安全 | 密码、2FA、带设备图标的会话列表与撤销                                       | 同样三张卡；不提供恢复码                                                             |
| 设置     | 外观、外壳、语言、存储、安全、演示数据、关于                                | 外观、语言、安全、保留策略、状态页预览、演示数据与关于                               |
| 主题     | 浅色/深色/跟随系统 + 强调色                                                 | 浅色/深色/跟随系统 + 同样的五种强调色                                                |
| 文件     | 可拖拽分栏、水印、轮播、JSON 查看器、可搜下拉与日期选择器                   | 固定两栏、缩略图墙、定义列表、下拉筛选、原生日期控件、平铺文件夹列表                 |
| 项目     | 精选轮播、统计卡、查询筛选器、里程碑日历、双栏穿梭、可编辑表格、评分/步骤条 | 精选卡片、KPI 卡片、单行筛选、分组里程碑列表、复选名单、行内预算表、星形按钮与步骤条 |
| 审批流   | 带虚拟滚动与列固定的 ProTable、JSON 查看器、Popconfirm、描述列表            | 普通表格、定义列表、共用一个确认对话框、直接复用包里的 `DateRangePicker`             |
| 其余页面 | 16 个功能                                                                   | 16 个页面加 `/roles/matrix` 与四个状态页                                             |

壳层与通知逐条偏差：

| 领域                       | React                                | Vue 模板                               | 原因                                                     |
| -------------------------- | ------------------------------------ | -------------------------------------- | -------------------------------------------------------- |
| 命令面板                   | `cmdk` + `CommandDialog`             | 自写输入框、过滤与 Dialog              | 单点使用不值得引依赖；过滤取子串匹配，不做 `cmdk` 打分配 |
| 产品导览                   | `packages/ui` 的 `Tour`              | 应用层 `Tour.vue`（自写 Portal）       | `packages/vue` 导出面冻结                                |
| `Segmented` / `Pagination` | `packages/ui` 导出                   | 应用层 `components/ui`                 | 同样因为导出面冻结                                       |
| 通知行悬浮预览             | `HoverCard`，300ms，展示正文         | 摘要直接放在行内，无悬浮层             | 少一个原语；信息没有丢失，只是提前展示                   |
| 静默时段                   | `TimePicker`                         | 原生 `<input type="time">`             | 两个字段不值得新造日期时间原语；值格式仍是 `HH:mm`       |
| 通知列表滚动区             | `ScrollArea`                         | `max-h-[520px] overflow-y-auto`        | 同上                                                     |
| 偏好保存提示               | `toast.success` / `toast.error`      | 卡片内 `role="status"` 文案            | 本模板无 toast 库（Slice 3 起的既定约定）                |
| 详情实体链接               | 项目、用户、文件与集成都可点         | 只链 `/integrations`，其余为纯文本     | 其余目标尚未交付，死链比没有链接更糟                     |
| 侧栏折叠状态               | `SidebarProvider` 写 cookie 且从不读 | 由 `ui` store 持久化                   | React 那个 cookie 是死代码；这里真的能记住               |
| `Ctrl/Cmd+B`               | `SidebarProvider` 注册               | `AppShell` 注册，`header` 布局不生效   | 没有侧栏时快捷键没有意义                                 |
| 服务端菜单                 | `GET /menu` 与 `enforceMenuAccess`   | 静态 `NAV_CONTRACT`                    | Slice 1 起的既定偏差，本切片不扩大                       |
| 页签 `search`              | 泛型 `Record<string, unknown>`       | `Record<string, string>`（只承载导航） | 页签不做筛选状态载体；筛选仍属各页                       |

DropdownMenu 包装组件把 CSS 变量从 `--radix-*` 改名为 `--reka-*`；其余 class 逐字复制 React 源码。

以下实现细节同样与 React 模板不同：

- `DropdownMenuItem` 与 `DropdownMenuLabel` 绑定 `:data-inset="inset || undefined"`，因此非 inset 项不渲染 `data-inset` 属性，而 React 渲染 `data-inset="false"`。
- 面包屑的分组标签是 `<li>` 内的普通 `<span>`，不带 `aria-current`；只有当前页那一项带。
- KPI 卡片省略了 React 的 `py-6` 内边距 class —— class 字符串来自计划，因此纵向内边距略有差异。本次工作没有新增或改动任何像素基线。
- 路由使用 `ShellLayout` 包装组件渲染 `AppShell` 加 `<RouterView>`，因为 `AppShell` 本身没有 `RouterView`（React 外壳的路由嵌套方式不同）。
- `eslint.config.js` 有一条只针对 `apps/vue-template/src/main.ts` 的覆盖，关闭 `react-hooks/rules-of-hooks`；该规则会对组件外的 Pinia `use*Store()` 调用误报。
- 权限矩阵在失效前先把 PUT 响应写回角色缓存，因此 refetch 失败不会把勾选回滚。
- 审计日志与集成页面接受服务端收敛后的页码，而不是继续请求用户点到的页码，因此结果集变小时分页器不会停在空页。
- 字典页从列表推导当前选中类型，而不是在 effect 里同步，因此删除选中类型后会立即收敛。
- 表格密度是 `DataTable` 的一个可选 `density` prop，只切换 React 用的那两对内边距（`py-3`/`h-10` 换 `py-1.5`/`h-9`），页面因此不必伸手改单元格 class，parity 场景也保持原渲染。
- CSV 辅助函数移到了 `src/lib/csv.ts`，因为现在有两个功能要写文件；用户导出按页取到 `total` 行为止（最多 200 页）再一次性写文件，因此中途失败不会留下半个下载。
- 保存视图只存查询字段、不存 `page`，并且应用时整份覆盖查询而不是合并 —— 否则「停用管理员」会保留上一条遗留筛选。
- 行选择以用户 id 为键，并在查询变化时清空：勾选一条已经不在结果集里的行，会让「删除所选」对用户不可见的事情生效。
- 撤销通知自己持有动作，两者一起消失；活得比提示更久的按钮会去恢复用户早已离开的那些 id。
- 表头的分组带由 `DataTable` 自己绘制：相邻且 `meta.group` 相同的可见叶子列成段，因为
  TanStack 没有这一行；它在两种密度下都是 32px，只要有一列没有分组就整条不渲染。
- 用户表的列布局（Columns 弹层里的拖拽排序、表头调宽手柄、持久化的顺序与列宽）在应用层：`column-order.ts` 对应 `packages/ui` 的纯函数，`packages/vue` 的 DataTable 只为可调宽的列渲染手柄，文档演示与 parity 基线不受影响。
- 审批流是第一个**直接复用**包里企业级原语的页面：`DateRangePicker` 本来就说 `{ from, to }` 的日字符串，并自带五个预设。其余缺的（表格、描述列表、JSON 查看器、Popconfirm、文本域）都在应用层。
- 通过 / 驳回 / 转交共用一个由 `pendingDecision` 驱动的确认对话框；三个常驻实例意味着三份文案和三处可能漏掉 destructive 的机会。
- 项目是本轮最大的一块移植（React 3,427 行），一个 feature 提交里含三部分：数据层与看板、详情壳与前两个页签、剩余页签与两个抽屉 —— 因为卡片链接到的详情路由必须同时存在。
- 替换了十六个原语，观感差别最大的两个是用「按天分组的里程碑列表」替代月历（组头复选框切换当天全部），以及用行内预算表替代可编辑表格组件。两者都写进了 spec。
- 文件页用应用层等价物替换了十二个 React 原语，逐项写在 spec 的对照表里：平铺缩进的文件夹列表替代 roving-tabindex 树、`Select` 替代可搜下拉、原生日期控件、定义列表替代 JSON 查看器、缩略图墙替代轮播、CSS 分栏替代可拖拽面板。上传串行执行 —— mock 的持久化是读-改-写，并发 POST 会互相覆盖并静默丢文件。
- CSV 解析与列映射/校验是纯模块（`lib/csv.ts`、`features/users/import.ts`），不依赖 DOM 就能测。向导本身是应用层组件：`packages/vue` 没有 `ImportWizard`，导出面又冻结，因此不必维护一个 35 字段的 labels 接口。
- 向导直接读 `users:import.*` 文案；没有 toast，页面把「创建 N 条」和「跳过 N 条」合成一条行内提示。上传复用 `Dropzone`，并给它加了可选的按钮文案 prop —— 中文的导入动作与通用企业文案不同。
- 详情头部直接写在 `UserDetailPage.vue` 里，没有新造 `DetailPage` 原语：只有一个消费者，而包的导出面是冻结的。九项资料用 `<dl>` 网格，而不是数据驱动的 `Descriptions` 组件。
- `Timeline`、`TagsInput`、`Dropzone` 同样放在应用层 UI 集。色调表与审计页共用，头像编码（`lib/image.ts`）与个人资料页共用，所以配色和 256px 裁切都不存在第二份。
- 找不到的用户用壳层内的 `EmptyState` 表达，而不是跳到全局 404 —— 那样会丢掉侧栏，用户还得自己找回列表。
- 没有页面级文档标题：这个模板没有对应帮手，页签工作区已经给出了路由名。
- 列标题与分组通过局部类型断言从 `columnDef.meta` 读取，而不做 `ColumnMeta` 模块增强：本仓库的 `@tanstack/table-core` 是传递依赖，增强没有稳定的模块路径可指。
- Reka 的 `AlertDialogAction` 只是关闭按钮的别名，所以共用 `AlertDialog` 改为渲染普通确认按钮，把 `open` 交给调用方控制；调用方在自己的 mutation 结束后再关闭。
- Reka 的 `PinInput` 以字符数组上报验证码，并额外渲染一个隐藏 input；`OtpInput` 统一归一成字符串，页面不需要知道这两件事。
- 页面通过 `useTransientMessage` 与 `role="status"` 段落就地反馈成功与失败 —— 模板不引入 toast 库。
- `packages/i18n` 与 React 模板共用，因此 `src/lib/i18n.ts` 在启动时覆盖唯一一处提到 React 的文案（`common:app.tagline`），而不是分叉语言包。
- 状态页放在 `ShellLayout` 之外，所以 `/401`、`/500`、`/503` 与 `/maintenance` 即使会话已失效也不会渲染侧边栏。
- Vue 会把缺省的布尔 prop 转成 `false`，这会让 Reka 的根组件变成受控且永久关闭。因此 `Dialog` 与 `Popover` 包装把 `open` 默认成 `undefined`，让原语在调用方绑定之前自己持有状态。
- `DialogContent` 会自带 `data-slot`，所以弹层内部与周围的定位改用专门属性（`data-command-palette`、`data-drawer-body`）。
- 「关闭右侧页签」是按位置切片，与 React 完全一致：右侧被固定的页签也会一并关掉。

### 页面契约

`e2e-vue-template/specs/pages.spec.ts` 走遍 `NAV_CONTRACT` 的每条路由，对每一页检查同样的五件事：页面能打开、只有一处标题且与侧栏标签一致、侧栏把该条目标为当前、控制台干净、axe 没有 serious 或 critical 违规。

第一次跑出两类系统性问题，都在壳层修掉而不是改十六个页面。页签条把 `role="tablist"` 套在包装 div 与操作按钮外面——tablist 只能拥有 tab，而每个 tab 还欠一个 tabpanel——所以它现在是一个带 `aria-current` 的 `nav`。另有四个页头控件的名称没有包含可见文字，会让语音控制失效：品牌链接漏掉了副标题、搜索按钮写着「Search…」却叫「Open command menu」、铃铛在隐藏 span 里重复了一遍数字、颜色选择器把十六进制值藏了起来。

这是页面级 parity 的结构性一半。两套实现是刻意不同的，跨应用截图 diff 比的是两个设计而不是同一份设计的两次构建；像素级 parity 依然不在范围内，`parity/` 下冻结的组件基线仍是视觉契约。

## 客户端权限边界

本模板的 RBAC 只作用于展示层。隐藏按钮或重定向路由都不能保护 API。Mock 服务跑在浏览器内部，同样不是安全边界。双因素流程只演示 UI 契约：验证码固定、密钥公开。
