# Vue 模板

`apps/vue-template` 是 FishAdmin 的私有 Vue 3 管理后台。它复用框架无关的 contracts、i18n 资源与 MSW Mock API，以及 `@fish-admin/vue` 组件移植。它是演示模板，不是发布包。

> 客户端权限是体验层，不是安全边界。路由守卫和按钮检查都可以在浏览器中被绕过；
> 真实部署必须在服务端执行授权校验。

## 范围

- 登录（含可选的双因素校验）、登出、会话恢复与 access token 刷新。
- 注册与邮箱验证、找回密码与重置密码、接受邀请——共六个认证入口，全部接到 Mock API。
- 账户域：个人资料（姓名、简介、头像）、账户安全（密码、会话、双因素）与设置（主题模式、强调色、语言、演示数据重置）。
- 按权限过滤的侧边栏、路由守卫与按钮级权限检查。
- 浅色 / 深色 / 跟随系统主题、五种强调色与 en / zh-CN 两种语言，均持久化。
- 工作台：7/30 天区间、四张 KPI 卡片、最近活动。
- 用户：搜索、状态筛选、服务端分页与排序、行操作、新建/编辑弹窗与删除确认。
- 报表：区间与粒度筛选、四张 KPI、渠道拆分与分页表格。
- 部门：`role="tree"` 与方向键导航、成员计数、就地新建与重命名。
- 角色：搜索、新建/重命名/删除，以及按角色逐个请求保存的权限矩阵。
- 权限：13 个分组的参考列表、分组视图与代码搜索。
- 字典：左右双栏维护类型与条目，含条目重排与启用/停用。
- 审计日志：动作、对象与日期筛选，服务端分页，以及带事件 metadata 与关联事件的详情抽屉。
- 集成：连接卡片、服务商与状态筛选、含请求头的表单抽屉，以及可重放的投递记录抽屉。
- 四个整页状态页（401、500、503、维护中），渲染在壳层之外；另有原有的 403 与 404 页。

不包含：顶栏/混合布局、密度与内容宽度设置、命令面板、通知、页签、子导航、离线横幅、产品导览、四个协作域页面、工作台图表、CSV 导入导出、保存视图、批量操作，也不做像素级 parity。`NAV_CONTRACT` 的 16 个页面中本模板交付 12 个，只缺协作域。

## 路由

| 路径               | 页面       | 访问条件                    |
| ------------------ | ---------- | --------------------------- |
| `/login`           | 登录       | 公开；已登录用户跳转 `/`    |
| `/register`        | 注册       | 公开；已登录用户跳转 `/`    |
| `/verify-email`    | 验证邮箱   | 公开；需要 `?token=`        |
| `/forgot-password` | 找回密码   | 公开；已登录用户跳转 `/`    |
| `/reset-password`  | 重置密码   | 公开；需要 `?token=`        |
| `/accept-invite`   | 接受邀请   | 公开；需要 `?token=`        |
| `/otp`             | 双因素     | 公开；需要 `?challenge=`    |
| `/`                | 工作台     | 已登录 + `dashboard:read`   |
| `/reports`         | 报表       | 已登录 + `report:read`      |
| `/users`           | 用户       | 已登录 + `user:read`        |
| `/departments`     | 部门       | 已登录 + `department:read`  |
| `/roles`           | 角色       | 已登录 + `role:read`        |
| `/roles/matrix`    | 权限矩阵   | 已登录 + `role:read`        |
| `/permissions`     | 权限       | 已登录 + `permission:read`  |
| `/dictionaries`    | 字典       | 已登录 + `dictionary:read`  |
| `/audit-logs`      | 审计日志   | 已登录 + `audit:read`       |
| `/integrations`    | 集成       | 已登录 + `integration:read` |
| `/profile`         | 个人资料   | 已登录；无权限键            |
| `/security`        | 账户安全   | 已登录；无权限键            |
| `/settings`        | 设置       | 已登录；无权限键            |
| `/403`             | 无权限     | 已登录                      |
| `/401`             | 会话失效   | 公开；整页，壳层之外        |
| `/500`             | 服务端错误 | 公开；整页，壳层之外        |
| `/503`             | 服务不可用 | 公开；整页，壳层之外        |
| `/maintenance`     | 维护中     | 公开；整页，壳层之外        |
| `/:pathMatch(.*)*` | 未找到     | 公开                        |

`/roles/matrix` 没有独立的侧边栏条目，入口在角色页头部；打开时侧边栏高亮仍落在角色。三个账户页对所有角色都出现在侧边栏，因为它们的路由不带 `meta.permission`。

## 认证链路

| 流程     | 路径                                     | 说明                                       |
| -------- | ---------------------------------------- | ------------------------------------------ |
| 注册     | `/register` → `/verify-email` → `/login` | Mock 返回验证 token，不发邮件。            |
| 找回密码 | `/forgot-password` → `/reset-password`   | 无论账号是否存在，响应一致。               |
| 接受邀请 | `/accept-invite?token=fish-demo-invite`  | 接受后直接登录并进入工作台。               |
| 双因素   | `/login` → `/otp` → `/`                  | 需先在 `/security` 启用；演示码 `246810`。 |

所有认证入口都会把已登录访客送回 `/`：注册、找回与 OTP 对已有会话的人没有意义。

## 与 React 模板的偏差

| 领域                                       | React                                               | Vue 模板                                               |
| ------------------------------------------ | --------------------------------------------------- | ------------------------------------------------------ |
| 外壳                                       | 侧边栏 / 顶栏 / 混合 + 密度与宽度设置               | 仅侧边栏；`/settings` 不出外壳卡片                     |
| 导航                                       | 契约中的全部 16 个页面                              | 16 个中的 12 个；只缺协作域                            |
| 命令面板 / 通知 / 离线横幅 / 页签 / 子导航 | 有                                                  | 无                                                     |
| 认证                                       | 登录、注册、找回密码、邀请、OTP、2FA                | 同样六条流程；不发邮件，TOTP 密钥固定                  |
| 工作台                                     | KPI、三张图表、产品导览                             | KPI 与活动流；无图表与导览                             |
| 用户                                       | 列控制、密度、保存视图、CSV、批量、导入、详情、动态 | 搜索、状态、分页、排序、增删改                         |
| 角色                                       | 两步式新建向导，第二步同时选权限                    | 单一弹窗；权限在矩阵中授予                             |
| 字典                                       | 拖拽手柄与方向键，无分页                            | 相同，条目列表不分页                                   |
| 审计日志                                   | JSON 查看器、按动作配图标、防抖搜索、页大小选择     | metadata 用定义列表、纯文字徽标、无防抖、每页 20       |
| 集成                                       | Combobox、Segmented 状态筛选、数字页码、Popconfirm  | Select 筛选、上一页/下一页、删除确认弹窗               |
| 个人资料                                   | 头像裁剪、上传进度、时区与语言偏好                  | 只有姓名、简介与头像；头像在本地重编码为 256×256       |
| 账户安全                                   | 密码、2FA、带设备图标的会话列表与撤销               | 同样三张卡；不提供恢复码                               |
| 设置                                       | 外观、外壳、语言、存储、安全、演示数据、关于        | 外观、语言、安全、保留策略、状态页预览、演示数据与关于 |
| 主题                                       | 浅色/深色/跟随系统 + 强调色                         | 浅色/深色/跟随系统 + 同样的五种强调色                  |
| 其余页面                                   | 16 个功能                                           | 12 个页面加 `/roles/matrix` 与四个状态页               |

DropdownMenu 包装组件把 CSS 变量从 `--radix-*` 改名为 `--reka-*`；其余 class 逐字复制 React 源码。

以下实现细节同样与 React 模板不同：

- `DropdownMenuItem` 与 `DropdownMenuLabel` 绑定 `:data-inset="inset || undefined"`，因此非 inset 项不渲染 `data-inset` 属性，而 React 渲染 `data-inset="false"`。
- 面包屑的分组标签是 `<li>` 内的普通 `<span>`，不带 `aria-current`；只有当前页那一项带。
- KPI 卡片省略了 React 的 `py-6` 内边距 class —— class 字符串来自计划，因此纵向内边距略有差异。本次工作没有新增或改动任何像素基线。
- 路由使用 `ShellLayout` 包装组件渲染 `AppShell` 加 `<RouterView>`，因为 `AppShell` 本身没有 `RouterView`（React 外壳的路由嵌套方式不同）。
- `eslint.config.js` 有一条只针对 `apps/vue-template/src/main.ts` 的覆盖，关闭 `react-hooks/rules-of-hooks`；该规则会对组件外的 Pinia `use*Store()` 调用误报。
- 权限矩阵在失效前先把 PUT 响应写回角色缓存，因此 refetch 失败不会把勾选回滚。
- 审计日志与集成页面接受服务端收敛后的页码，而不是继续请求用户点到的页码，因此结果集变小时分页器不会停在空页。
- 字典页从列表推导当前选中类型，而不是在 effect 里同步，因此删除选中类型后会立即收敛。
- Reka 的 `AlertDialogAction` 只是关闭按钮的别名，所以共用 `AlertDialog` 改为渲染普通确认按钮，把 `open` 交给调用方控制；调用方在自己的 mutation 结束后再关闭。
- Reka 的 `PinInput` 以字符数组上报验证码，并额外渲染一个隐藏 input；`OtpInput` 统一归一成字符串，页面不需要知道这两件事。
- 页面通过 `useTransientMessage` 与 `role="status"` 段落就地反馈成功与失败 —— 模板不引入 toast 库。
- `packages/i18n` 与 React 模板共用，因此 `src/lib/i18n.ts` 在启动时覆盖唯一一处提到 React 的文案（`common:app.tagline`），而不是分叉语言包。
- 状态页放在 `ShellLayout` 之外，所以 `/401`、`/500`、`/503` 与 `/maintenance` 即使会话已失效也不会渲染侧边栏。

## 测试

Vitest 覆盖重定向、权限、认证/会话、i18n、主题、登录、注册、验证、找回、邀请与 OTP 页、三个账户页、四个状态页、侧边栏与全部管理页：46 个文件共 297 条用例。十四条 Playwright 用例覆盖主流程、四条管理域场景（9 个导航项、访客 403、矩阵保存后刷新仍生效、分页器回收）与四条认证/账户场景（注册—验证—登录、重置密码、接受邀请、强调色刷新后仍生效）；它们不生成也不比对截图。

## 客户端权限边界

本模板的 RBAC 只作用于展示层。隐藏按钮或重定向路由都不能保护 API。Mock 服务跑在浏览器内部，同样不是安全边界。双因素流程只演示 UI 契约：验证码固定、密钥公开。
