# Editable Table 可编辑表格

`EditableTable` 用你传入的 `rows` 渲染一张语义化 `<table>`，并逐行把内容切换为 `Input`、原生
`<select>` 与 `Button`。列定义负责编辑器类型、`parse` 转换与 `validate` 规则，只有保存成功的行
才会写回你的数据。

<ComponentMeta id="editable-table" />

## 何时使用

- 配置类表格，每行少量字段需要频繁调整，例如负责人、投递方式、配额。
- 数据完全在客户端、不需要排序分页的小规模行集合。
- 需要先把非法值挡在校验里，再让它们进入存储。

## 何时不使用

- 只读列表，但需要搜索与批量操作：使用 `ProTable`。
- 服务端分页、需要排序的长表格：使用 `ProTable` 并自行持有 TanStack 实例。
- 单条记录的表单而不是网格：使用 `ProForm` 或 `Form`。

## 设计指引

- 同一时刻只展开一行：内部用 `editingId` 与该行 `draft` 副本工作，因此取消与 Escape 是丢弃草稿，
  而不是回滚已保存的数据。
- 展开的行使用 `bg-muted/30` 高亮；单元格始终是 `px-3 py-2` 且 `align-top`，编辑器撑高时不会挤动
  相邻单元格。
- 编辑器高度 32 px（`h-8`）：`Input` 带 `min-w-32`，下拉带 `min-w-28`，都保留
  `focus-visible:ring-2 focus-visible:ring-ring/50`。校验失败时边框换成 `border-destructive`，
  提示文字用 `text-xs text-destructive` 显示在字段下方。
- `editor` 决定控件：`'number'` 渲染 `type="number"`，`'select'` 使用 `column.options`，其余按文本
  处理；不写 `editor` 时同样是文本框。
- 保存时先对每一列执行 `parse`（入参是 `String(value ?? '')`），再把解析后的值和整行候选数据交给
  `validate`。只要有一条消息，本次 `onRowsChange` 就不会发生。
- `render` 只在只读状态执行，适合把方案 id 或数字格式化；值为空或 `undefined` 时显示弱化色的 `—`。
- `addRow` 同时决定“新增”按钮是否出现以及草稿内容，保存后新行追加到末尾。请保证 `id` 唯一——行以
  `id` 作为 key，`__new__` 是内部保留的哨兵值。
- 组件会自动追加操作列，因此空状态的 `colSpan` 是 `columns.length + 1`。`labels.actions` 请保持简短，
  该列右对齐且 `whitespace-nowrap`。
- 宽表在 `overflow-x-auto rounded-lg border` 容器内横向滚动，表格自身是 `min-w-[40rem]`；新增按钮
  位于表格外框右上角。

## 无障碍

- 使用真实表格结构：`aria-label` 为表格命名，每个 `<th>` 都有 `scope="col"`，操作列表头同样是
  `<th>`。
- 编辑器通过 `aria-label={column.header}` 获得名称，读屏会念出“Owner, 编辑”；出错字段带上
  `aria-invalid`。
- 编辑与删除图标按钮的可访问名称由 `rowLabel` 拼成，形如“编辑 Ada Lovelace”，`Pencil`/`Trash2`
  图标设为 `aria-hidden`。
- Escape 会取消当前行；所有控件都是 `type="button"`，行内编辑不会误提交外层表单。
- 滚动容器设置 `tabIndex={0}`，键盘用户可以横向滚动宽表；外层包裹是 `role="presentation"`。

已知缺口：展开某一行时不会把焦点移入第一个字段；错误提示只是普通文本，既没有 `aria-describedby`
关联，也没有放入活动区域，读屏用户需要 Tab 回单元格才能知道保存为何被拒绝。另外所有文案都要由调用方
通过 `labels` 传入，组件不含默认文本。

## FAQ

**组件会替我保存未提交的修改吗？** 只保留当前行的 `draft` 副本。校验通过前不会调用
`onRowsChange`，取消或 Escape 直接丢弃草稿。

**为什么拿到的是字符串而不是数字？** 不写 `parse` 时存的是输入框原始值。加上
`parse: (raw) => Number(raw)`，`validate` 才能读到数字。

**可以同时编辑两行吗？** 不行，`editingId` 一次只允许一行，跨行规则只能依赖被编辑行自身的数据。

**删除会怎么处理未保存的编辑？** 立即通过 `onRowsChange` 移除该行，如果被删的正是展开行，编辑器会
一并关闭。
