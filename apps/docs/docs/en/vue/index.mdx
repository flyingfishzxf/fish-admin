# Vue 3 package

`@fish-admin/vue` is the Vue 3 port of this library. It ships **90 component exports**: all 83 React
ids have a Vue implementation, plus 7 Vue-only components. Every component has demos in both themes.

## Status

| Surface         | React              | Vue                                   |
| --------------- | ------------------ | ------------------------------------- |
| Components      | 83                 | 90 (83 shared + 7 Vue-only)           |
| Docs            | Bilingual per page | Vue overview + component catalog here |
| Demos           | 167 TSX            | 181 SFC in `apps/parity-vue`          |
| Visual baseline | 6 pilot × 2 themes | 6 pilot cross-version + 90 self × 2   |
| Unit tests      | 93 files           | 71 files / 248 tests                  |

The **component catalog** lists every Vue export with its demos: <Link href="/vue/components">Browse all 90 components</Link>.

## Install

```bash
pnpm add @fish-admin/vue
```

Vue is a peer dependency (`^3.5.45`). The package carries its own styles; import them once:

```ts
import '@fish-admin/vue/styles.css'
```

## How the port relates to React

Shared, framework-neutral packages (`@fish-admin/contracts`, `@fish-admin/i18n`, `@fish-admin/mock`)
are consumed by both versions. The Vue package uses Reka UI primitives and self-built replacements
for the React-only libraries (sonner, react-hook-form, cmdk, resizable). Chart renders through
`@unovis/vue`; the render layer is the one runtime dependency the Vue package adds.

A few APIs are intentionally different, not missing:

- Form is a config-driven `ProForm` alias rather than a React Hook Form wrapper.
- Calendar is single-select; use `DateRangePicker` for a range.
- `TourStep.target` takes a CSS selector rather than an element callback.
- Breadcrumb renders a plain `<a>` to keep `vue-router` out of the package boundary.

The 6 pilot components (Accordion, DateRangePicker, Dialog, ProTable, Select, Tabs) are matched
pixel-for-pixel against the frozen React screenshots. The other components have their own
self-baselines in `e2e-vue-visual`, so a visual regression is caught without pretending two
different implementations must look identical.

## Running the Vue demos locally

The demos live in `apps/parity-vue`, not in this React-authored docs site (whose CSP forbids
framing and whose bundler cannot render `.vue` files):

```bash
pnpm --filter @fish-admin/parity-vue dev
```

Open `http://localhost:4176` and pick a component. The catalog links each demo to its source file.

## Verification commands

```bash
pnpm test:vue                  # Vue package + parity-vue unit tests

pnpm test:vue-visual:docker    # 90-component self-baseline comparison
pnpm check:vue-visual:freeze   # baseline manifest integrity
pnpm check:package             # export surface, React 83 + Vue 90
```
